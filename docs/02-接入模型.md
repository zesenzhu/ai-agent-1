# 02 接入模型

## 协议要求

客户端只依赖 Chat Completions 的三件事：

1. `POST {baseUrl}/chat/completions`，请求体含 `model`、`messages`、可选 `tools`、`stream`；
2. 响应要么是 JSON（`choices[0].message`），要么是 SSE（`choices[0].delta`），末帧 `data: [DONE]`；
3. 支持 `tools` 时返回 `tool_calls`，其中 `function.arguments` 是 JSON 字符串。

只要满足这三条，任何供应商都能直接用。**不支持 function calling 的模型**也能跑，但工具永远不会被调用——它只会聊天。

## 配置优先级

```text
命令行参数  >  进程环境变量  >  .env 文件  >  内置默认值
```

`.env` 由 `src/config.ts` 自己解析（不引入 dotenv），已存在的环境变量不会被覆盖。所以临时切换模型不用改文件：

```bash
OPENAI_MODEL=deepseek-reasoner pnpm start
```

## 各家配置

| 供应商 | `OPENAI_BASE_URL` | `OPENAI_MODEL` 示例 |
| --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Moonshot | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 阿里百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` |
| 本地 Ollama | `http://localhost:11434/v1` | `qwen2.5:7b` |

Ollama 的 `OPENAI_API_KEY` 填任意非空字符串（例如 `ollama`），它不校验。

```bash
# 本地 Ollama 完整示例
ollama pull qwen2.5:7b
OPENAI_BASE_URL=http://localhost:11434/v1 \
OPENAI_API_KEY=ollama \
OPENAI_MODEL=qwen2.5:7b \
pnpm start
```

本地小模型的工具调用能力普遍偏弱：常见表现是「只在聊天里描述要做什么，不真的调用」。先把工具描述写清楚，再考虑换模型。

## 环境变量

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | 服务地址，**不要**带 `/chat/completions` |
| `OPENAI_API_KEY` | 必填 | 鉴权 |
| `OPENAI_MODEL` | 必填 | 模型名 |
| `AGENT_TEMPERATURE` | `0.3` | 工具调用场景建议 0～0.3，越低越稳定 |
| `AGENT_MAX_STEPS` | `8` | 单轮最多几次模型调用 |
| `AGENT_MAX_HISTORY` | `40` | 非 system 消息保留条数 |
| `AGENT_WORKSPACE` | 当前目录 | 文件工具沙箱 |
| `AGENT_SESSION_FILE` | `.agent-session.json` | 会话文件 |
| `AGENT_STREAM` | `true` | 关掉可看完整响应体 |

## 排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `401 Unauthorized` | Key 错、过期、或复制时带了空格 | 重新生成；`OPENAI_API_KEY` 不要加引号以外的字符 |
| `404 Not Found` | `baseUrl` 写成了 `.../chat/completions`，或漏了 `/v1` | 只填到版本号那一层 |
| `400 tool_calls` 相关 | 历史里 `assistant(tool_calls)` 与 `tool` 消息没配对 | 本示例已在裁剪时规避；自定义存储时注意成对保存 |
| `400 tools is not supported` | 该模型不支持 function calling | 换模型，或去掉 `tools` |
| 一直重复调用同一个工具 | 模型认为结果不合格，或工具返回内容难以理解 | 让工具返回文本更结构化，例如带上字段名；或降低 `AGENT_MAX_STEPS` |
| 中文输出成乱码 | 少见，多为终端编码问题 | `LANG=zh_CN.UTF-8` |
| 请求超时 | 默认 120s | 换网络，或检查 `baseUrl` 是否可直连 |

## 不用真模型也能调试

```bash
pnpm mock-llm
# 另开一个终端
OPENAI_BASE_URL=http://127.0.0.1:11435/v1 \
OPENAI_API_KEY=mock OPENAI_MODEL=mock-model pnpm start
```

mock 服务的行为是脚本化的：第一次返回 `calculate` 调用，收到工具结果后返回一段固定答复。它专门把工具调用拆成多片（名字 `calc` + `ulate`），用来验证客户端的增量拼接。

想看原始响应，用 curl 直接打：

```bash
curl -s http://127.0.0.1:11435/v1/chat/completions \
  -H 'content-type: application/json' \
  -d '{"model":"mock-model","stream":true,"messages":[{"role":"user","content":"算 (12+3)*4"}]}'
```

## 关闭流式

```bash
pnpm start -- --no-stream
```

流式是给人看的；非流式在日志、测试和抓包里更好读。客户端会自动识别响应类型：服务端忽略 `stream:true` 时，仍按 JSON 解析。
