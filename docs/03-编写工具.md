# 03 编写工具

工具是 agent 的手脚。写一个工具只需要三件事：**名字**、**给模型看的描述**、**参数声明**。执行逻辑是普通的 async 函数。

## 最小可用工具

新建 `src/tools/word-count.ts`：

```ts
import { readFile } from 'node:fs/promises';
import { resolveInsideWorkspace } from './fs.js';
import type { Tool } from './types.js';

export const wordCountTool: Tool = {
  name: 'word_count',
  description: '统计工作目录内某个文本文件的行数、字符数和词数。',
  parameters: {
    type: 'object',
    properties: {
      path: { type: 'string', description: '相对工作目录的文件路径' },
    },
    required: ['path'],
  },
  async run(args, context) {
    const path = String(args.path);
    const absolute = resolveInsideWorkspace(context.workspace, path);
    const text = await readFile(absolute, 'utf8');
    const lines = text === '' ? 0 : text.split('\n').length;
    const words = text.split(/\s+/).filter(Boolean).length;
    return `文件 ${path}：${lines} 行，${text.length} 字符，${words} 个词`;
  },
};
```

在 `src/tools/index.ts` 注册：

```ts
import { wordCountTool } from './word-count.js';

export function createDefaultTools(): Tool[] {
  return [getCurrentTimeTool, calculateTool, readFileTool, writeFileTool, listDirTool, httpGetTool, wordCountTool];
}
```

跑起来：

```bash
pnpm start -- --prompt "统计 package.json 有多少行"
```

就这么多。不需要改 agent 循环，不需要改提示词——下一轮请求里 `tools` 数组会自动多出这一项。

## 接口

```ts
export interface Tool {
  name: string;                 // 模型调用的标识，建议 snake_case，全局唯一
  description: string;          // 给模型看：做什么、什么时候用、有什么限制
  parameters: JsonSchema;       // 参数声明，同时用于给模型和运行时校验
  run(args: Record<string, unknown>, context: ToolContext): Promise<string> | string;
}
```

`run` 的返回值是**给模型读的文本**，不是给用户读的。区别很重要：

- 模型读的：字段清晰、信息完整，例如 `状态码：200\n内容类型：application/json\n---\n{...}`；
- 用户读的：由模型在最终答复里重新组织。

所以工具不要返回 `OK`，要返回模型能判断下一步的内容。

## 参数声明支持的子集

`src/tools/schema.ts` 实现了一个够用的子集：

| 字段 | 作用 |
| --- | --- |
| `type` | `object` / `string` / `number` / `integer` / `boolean` / `array` |
| `properties` | 对象字段声明 |
| `required` | 必填字段名列表 |
| `items` | 数组元素声明 |
| `enum` | 枚举取值 |
| `minimum` / `maximum` | 数值区间 |
| `description` | 字段说明，模型会读 |

不支持 `oneOf`、`$ref`、`pattern`。需要这些时换 zod / ajv，只需替换 `validateArgs` 的实现，接口不用动。

## 错误即结果

**工具永远不要抛异常给模型看。** 注册表的 `execute()` 已经兜底：

| 情况 | 回填给模型的内容 |
| --- | --- |
| 工具名不存在 | `未知工具「x」。可用工具：…` |
| 参数不是合法 JSON | `参数不是合法 JSON：…` |
| 参数校验失败 | `参数校验失败：arguments.expression 缺失` |
| `run` 内部抛错 | `工具执行失败：ENOENT: no such file…` |

这样模型有机会自我修正。在 `run` 里主动抛错也是合法写法——错误信息就是给模型的提示：

```ts
if (info.isDirectory()) throw new Error(`${path} 是目录，请使用 list_dir`);
```

反例是「静默返回空字符串」：模型会以为调用成功，然后编一个结果出来。

## 安全边界

工具是模型能触达的全部能力，写错一个就等于把系统交出去。现有实现里的四条规矩：

1. **文件路径必须过沙箱**。`resolveInsideWorkspace()` 用 `resolve` + `relative` 判断是否越界，`../`、绝对路径、`a/../../b` 都会被拦。
2. **只做该做的事**。`http_get` 只有 GET；没有写外部状态的工具。
3. **有超时和长度上限**。`http_get` 15s 超时、默认 4000 字符；`read_file` 默认 6 万字符。工具输出会占用模型上下文，无限返回等于烧钱。
4. **不把敏感信息回填**。工具输出会进入模型上下文，进而可能进入日志。密钥、token、用户隐私字段不要出现在返回值里。

如果要加 `shell` 类工具，先想清楚：命令白名单？工作目录限制？输出截断？超时？默认不批准？——四项缺一项就不该上线。

## 描述怎么写

模型的工具选择完全依赖 `name` 和 `description`。同一份代码，描述不同，效果差很远：

| 写法 | 结果 |
| --- | --- |
| `description: '计算器'` | 模型经常不用，直接心算 |
| `description: '计算数学表达式，支持 + - * / % ^ 和括号，返回精确到 12 位有效数字的结果。'` | 遇到算式会调用，且知道不要传中文单位 |

三条经验：

- 写**边界**，不只写功能：`只支持 http/https`、`最多 200 条`、`大文件会被截断`；
- 写**何时用**：「需要当前时间时使用」比「获取时间」有效；
- 参数描述写**示例值**：`'IANA 时区名，例如 Asia/Shanghai、UTC'`。

## 测试

每个工具至少三个用例，`test/tools.test.ts` 里的现成写法：

```ts
test('工具正常路径', async () => {
  const result = await registry.execute('calculate', '{"expression":"2*(3+4)"}', context);
  assert.equal(result.content, '2*(3+4) = 14');
});

test('参数非法时返回错误文本而不是抛异常', async () => {
  const result = await registry.execute('calculate', '{}', context);
  assert.equal(result.ok, false);
  assert.match(result.content, /arguments\.expression 缺失/);
});

test('越界访问被拒绝', async () => {
  const result = await registry.execute('read_file', '{"path":"../../etc/passwd"}', { workspace: '/tmp/work' });
  assert.equal(result.ok, false);
  assert.match(result.content, /路径越界/);
});
```

有文件副作用的工具用 `mkdtemp` 建临时目录，测试结束 `rm`，不要写进仓库目录。

## 记账场景的示例骨架

如果把 agent 接到 `xb-jizhang` 主项目上，工具应该调用主项目的 API，而不是直连数据库：

```ts
export const createTransactionTool: Tool = {
  name: 'create_transaction',
  description: '新增一笔账单。金额单位为分，必须为正整数；需要账本 ID、账户 ID、分类 ID。',
  parameters: {
    type: 'object',
    properties: {
      ledgerId: { type: 'string', description: '账本 ID' },
      amount: { type: 'integer', description: '金额（分），例如 12.5 元填 1250', minimum: 1 },
      type: { type: 'string', enum: ['income', 'expense'] },
      categoryId: { type: 'string' },
      occurredAt: { type: 'string', description: 'ISO 8601 时间' },
    },
    required: ['ledgerId', 'amount', 'type', 'categoryId'],
  },
  async run(args, context) {
    // 关键：带上当前用户的访问令牌，让主项目的账本权限校验生效，
    // 而不是用服务账号绕过权限。
    const response = await fetch(`${process.env.API_BASE_URL}/api/transactions`, {
      method: 'POST',
      headers: { 'content-type': 'application/json', authorization: `Bearer ${context.userToken}` },
      body: JSON.stringify({ ...args, clientId: crypto.randomUUID() }),
    });
    if (!response.ok) throw new Error(`创建失败：${response.status} ${await response.text()}`);
    return `已创建账单：${JSON.stringify(await response.json())}`;
  },
};
```

三个约束（对应主项目 `.agent/AGENTS.md`）：金额用整数分、新增必须带客户端幂等 ID、权限校验不能信客户端传的 `ledgerId`。写操作类工具还应加**人工确认**，见 `04-会话与扩展.md`。

注意上面用到的 `context.userToken` 需要先扩展 `ToolContext`（当前只有 `workspace` 与 `signal`），并在调用 `agent.run()` 时把当前请求的用户令牌传进去——这是把示例接进真实业务时最小的一处改动。
